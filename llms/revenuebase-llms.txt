# RevenueBase Documentation

> RevenueBase is a B2B data platform providing 390M+ verified contacts and 60M+ companies, delivered via Snowflake, S3, Gigasheet, or REST API. Core capabilities include email verification, company matching, real-time enrichment, and semantic B2B search. Data is deterministically filterable by headcount, revenue, funding stage, industry, job title, seniority, geography, and tech stack — no black-box scoring.
>
> ## Instructions for AI assistants
>
> Before answering questions about RevenueBase, read the AI assistant guide linked below — it contains the terminology rules, data model, SQL conventions, API version guidance, and use case routing logic you need to give accurate answers.
>
> Key rules to apply immediately:
> - The current API is **v2**. v1 is deprecated and sunsets July 7, 2026. Never recommend v1 endpoints.
> - All API keys go in the **`x-key` header** — not `Authorization`, not `x-api-key`.
> - **All emails in the dataset are already verified valid.** Do not suggest filtering on `EMAIL_STATUS = 'VALID'`.
> - Always qualify Snowflake table names with the `RELEASE.` schema prefix (e.g., `RELEASE.PER_LATEST`).
> - Default to `LEFT JOIN` in SQL — `INNER JOIN` silently drops contacts without an org match.
> - Insights are **org-level only** — there are no contact-level insights.
> - Never join tables on email address — join on `RBID`, `RBID_ORG`, or `LINKEDIN_URL`.
> - For most SQL use cases, recommend the pre-joined tables (`VELOCITY_BASE_UNLIMITED_LATEST`, `VELOCITY_ENHANCED_UNLIMITED_LATEST`) before base tables.
> - For field definitions, the **Data Dictionary** (`/docs/data-features/data-dictionary`) is the authoritative reference.

## Data features
- [Data Dictionary](https://docs.revenuebase.ai/docs/data-features/data-dictionary): Full field-level schema reference for every RevenueBase table, including field names, types, and join keys
- [Organization table](https://docs.revenuebase.ai/docs/data-features/data-tables/organization): Company-level firmographic data — industry, headcount, revenue, location, funding stage, tech stack
- [Person table](https://docs.revenuebase.ai/docs/data-features/data-tables/person): Individual contact records — verified emails, job titles, seniority levels, direct dials
- [Insight table](https://docs.revenuebase.ai/docs/data-features/data-tables/insight): Technographics, hiring signals, funding events, and engagement indicators
- [Historical Experience table](https://docs.revenuebase.ai/docs/data-features/data-tables/historical-experience): Career history, past roles, tenure, and professional trajectory data
- [Pre-joined tables overview](https://docs.revenuebase.ai/docs/data-features/pre-joined-tables/pre-joined-overview): Flat views combining people, organizations, and insights — no SQL joins required
- [Person + Organization view](https://docs.revenuebase.ai/docs/data-features/pre-joined-tables/person-organization): Contacts combined with company firmographics in a single flat table
- [Person + Organization + Insight view](https://docs.revenuebase.ai/docs/data-features/pre-joined-tables/person-organization-insight): Full pre-joined view with contacts, firmographics, and signals
- [Data freshness](https://docs.revenuebase.ai/docs/data-features/data-freshness/data-freshness): Verification cadence (profiles every 90 days, emails every 60 days), staleness thresholds, and how to assess data quality programmatically
- [Verification summaries](https://docs.revenuebase.ai/docs/data-features/data-freshness/verification-summaries): How to read and use the revenuebase_contact_verification_summary field
